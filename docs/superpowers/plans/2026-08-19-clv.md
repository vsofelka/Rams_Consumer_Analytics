# Customer Lifetime Value (CLV) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a dynamic, per-fan-per-week Customer Lifetime Value estimate that reuses the
existing churn/engagement pipeline's data, flows through SQLite and BigQuery the same way
every other column already does, and surfaces as a dollar figure alongside the existing
at-risk list.

**Architecture:** A new pure-function module, `scoring/clv.py`, computes CLV from three
values `scripts/run_season.py`'s weekly loop already has in hand (`plan_tier`,
`engagement_tier`, `at_risk`). The result becomes one new column, `clv`, on the existing
`weekly_snapshots` table/CSV — no new tables, no new files downstream, no new BigQuery
view (only one existing view gains a column).

**Tech Stack:** Python, pandas, sqlite3, pytest, `unittest.mock`. No new dependencies.

**Spec:** [`docs/superpowers/specs/2026-08-19-clv-design.md`](../specs/2026-08-19-clv-design.md)

## Global Constraints

- Formula: `CLV = ANNUAL_VALUE[plan_tier] * EXPECTED_REMAINING_YEARS[engagement_tier] * (AT_RISK_DISCOUNT if at_risk else 1.0)`
- `ANNUAL_VALUE`: `{"standard": 2000, "premium": 6000, "club": 15000}` — placeholder dollar
  figures, pending real pricing data
- `EXPECTED_REMAINING_YEARS`: `{"Super Fan": 8, "Engaged": 5, "Cooling": 2, "Dormant": 0.5}`
  — placeholder retention assumption, keyed on the exact tier label strings from
  `scoring/engagement.py:38` (`["Dormant", "Cooling", "Engaged", "Super Fan"]`)
- `AT_RISK_DISCOUNT = 0.5`
- Sanity checks (must hold exactly): `estimate_clv("club", "Super Fan", False) == 120000.0`;
  `estimate_clv("standard", "Dormant", True) == 500.0`
- No defensive error handling for invalid `plan_tier`/`engagement_tier` values — inputs are
  always controlled by the pipeline, matching this repo's existing convention
  (`scoring/churn.py`, `scripts/load_to_bigquery.py` follow the same rule)
- Test naming: `test_<function>_<expected_behavior>`, flat module-level functions, no
  `Test` classes, no pytest fixtures — matching `tests/test_churn.py`
- This plan does not touch `season_simulator/`, the engagement score formula, the churn
  rule itself, or any Power BI file — those are explicitly out of scope per the spec

# Placeholder dollar/retention assumptions, pending real Rams pricing and
# renewal-rate data — see docs/superpowers/specs/2026-08-19-clv-design.md.
# Every value here is independently swappable once real figures exist.

ANNUAL_VALUE = {
    "standard": 2000,
    "premium": 6000,
    "club": 15000,
}

EXPECTED_REMAINING_YEARS = {
    "Super Fan": 8,
    "Engaged": 5,
    "Cooling": 2,
    "Dormant": 0.5,
}

AT_RISK_DISCOUNT = 0.5


def estimate_clv(plan_tier, engagement_tier, at_risk):
    base = ANNUAL_VALUE[plan_tier] * EXPECTED_REMAINING_YEARS[engagement_tier]
    if at_risk:
        return base * AT_RISK_DISCOUNT
    return base
```

---

## 2026-08-19 — Added a dynamic Customer Lifetime Value estimate alongside churn

**Decision:** Add `scoring/clv.py`, computing a per-fan, per-week CLV estimate from
`plan_tier`, the current engagement tier, and the `at_risk` flag — reusing exactly the same
data the churn view already produces, with no new simulator or validation methodology. The
result is one new `clv` column on `weekly_snapshots`, flowing through the same SQLite →
BigQuery pipes as every other column.

**Why:** The job posting names customer lifetime value explicitly, alongside churn
(`docs/job_description.md`), and the project previously had no dollar-value story — every
churn number was a count ("13 fans flagged"), not a business figure. Making CLV dynamic
(recalculated per week off the current engagement tier, with an additional discount when a
fan is flagged at-risk) ties it directly to the existing churn signal instead of sitting
next to it as an unrelated static number.

Unlike the churn rule, CLV has no equivalent ground truth to validate against — there's no
planted "true lifetime value" to measure precision/recall against the way there is for
churn. Every dollar figure and retention-years assumption here (`docs/superpowers/specs/2026-08-19-clv-design.md`)
is a clearly labeled placeholder pending real Rams pricing and renewal-rate data, not a
fitted or validated model. This is a deliberate honesty choice: the docs say so directly
rather than implying a rigor the estimate doesn't have.

**Reference:** [`docs/superpowers/specs/2026-08-19-clv-design.md`](superpowers/specs/2026-08-19-clv-design.md).
```
